?? Shopping Cart and Checkout Flow Design
Overview
My food order app implements a robust and modern e-commerce flow using localStorage for cart management and a database for final order persistence. This approach ensures both user experience smoothness and backend data integrity.
Step-by-Step Logic
1. Cart Management with localStorage
When users add items to their cart, all changes are stored exclusively in the browser's localStorage.
No order data is persisted to the database during the shopping phase.
This keeps the database clean and avoids accumulating incomplete or abandoned orders.
2. Proceed to Checkout
When the user navigates to the checkout confirmation page (¡§Confirm Checkout¡¨), the app reads the entire cart from localStorage.
At this point, the client sends the cart data to the backend via an server action
The server creates a new order record in the database with the status set as pending or unpaid.
If the user already has a pending order, the previous one will be replaced or updated to reflect the latest cart contents, ensuring only one up-to-date order per user.
3. Cart Changes after Checkout Initiation
If the user navigates back to the cart or shopping page and modifies the cart (e.g., adding/removing items), the process repeats:
Upon returning to the confirm checkout page, the latest cart is sent to the backend, and the existing pending order in the database is updated or replaced.
This guarantees the order in the database always matches the most recent user intent, and eliminates the risk of stale or duplicate pending orders.
4. Payment with Stripe
When the user clicks ¡§Confirm Checkout,¡¨ the backend uses the order information to initiate a Stripe payment session.
After successful payment, a Stripe webhook updates the corresponding order¡¦s status in the database to paid.
This backend-driven approach ensures payment confirmation and order updates are always reliable, even if the user closes the tab or disconnects during payment.
Key Benefits
Data Consistency: Only finalized orders are stored in the database, reducing clutter and ensuring high data integrity.
Robustness: The backend is always in sync with the latest user cart state, and the use of Stripe webhooks guarantees payment status accuracy.
User Experience: The localStorage-first approach enables fast and smooth cart interactions, with database writes deferred until the user is ready to check out.
Conclusion
This flow combines best practices from both frontend and backend development, providing a seamless user experience and a clean, reliable order system in the database.
